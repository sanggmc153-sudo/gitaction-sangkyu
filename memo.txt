CI
 - 코드를 올릴때마다 자동으로 검사해주는 것!
 - 여러명이 코드를 합칠 때 오류가 생길 수 있음
 - 그래서 깃허브한테 자동 검사 담당자 
 - 깃허브 작은 컴퓨터를 하나 빌려서 자동으로 검사 하는것!

Ruuner
 -  작업을 실행하는 컴퓨터들 (일회용)

동작하는 환경 
 - 우툰트(리눅스)
 - 윈도우
 - 맥 OS

CI 실행 순서 
 - 먼저 자동 코드 검사를 할 프로젝트 선택!
 - 그 안에 .github 폴더 생성!
 - 그 안에 고정된 폴더명 바꾸면 안된다 깃액션이 모른다!
   workflows
 - 할일 작성하기 
   파일명 아무거나 해도 된다! yaml 확장자 사용하기

ci.yaml 파일 생성후 안에 작성!
1. name : 어떤 작업파일 이름 붙인다.
2. on : 언제 실행할지 실행을 여러개 설정할 수있다 []
3. jobs: 작업할 내용을 순서대로 적는다!
4. helloprint : 어떤작업인지 이름달수 있다. 아무거 작성해도 된다.
5. runs-on : 어떤 운영체제에서 동작 할건지 선택해야된다!

배포를 할 때 깃허브 pages 안에 두 가지 방식 
Deploy from a branch 
 - 기본적으로 지정한 브랜치HTML 파일을 사이트로 배포!
 - /root 폴더 안에 index.html 파일이름도 고정해야된다!
 - save를 꼭 누른다.

Github Actions 배포 
 - push -> HTML 검사 -> 성공하면 배포/실패하면 중단
 - 내가 원하는 데로 yaml파일을 작성해서 배포하고싶을때!

name: HTML 검사 후 배포

# main 브랜치에 push하면 실행
on:
  push:
    branches: [main]

# 배포에 필요한 권한
permissions:
  contents: read
  pages: write
  id-token: write

# 배포 작업이 겹치지 않게 설정
concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  deploy:
    runs-on: ubuntu-latest

    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}

    steps:
      # 1. 저장소 코드 가져오기
      - uses: actions/checkout@v6

      # 2. Node.js 준비
      - uses: actions/setup-node@v4
        with:
          node-version: '22'

      # 3. HTML 검사: 실패하면 이후 단계는 실행 안 됨
      - name: HTML 검사
        run: npx --yes html-validate --rule close-order:error index.html

      # 4. GitHub Pages 준비
      - uses: actions/configure-pages@v5

      # 5. 배포할 파일만 별도 폴더에 담기
      - name: 배포 파일 준비
        run: |
          mkdir -p public
          cp index.html public/

      # 6. 배포 파일 업로드
      - uses: actions/upload-pages-artifact@v3
        with:
          path: public

      # 7. 사이트 배포
      - name: 사이트 배포
        id: deployment
        uses: actions/deploy-pages@v4

CD
 - 검사한 코드를 실제 서비스에 배포하는 과정!
 - 코드를 올리면 자동으로 CI검사를 하고 통과 하면 CD 실제
   사이트까지 바꿔주는 역할 

접속하는 서버들이 key들을 가지고 있다면 
Actions secrets and variables 에 저장해서 쓴다.(내컴퓨터 환경변수설정)
저장소 선택 -> settings -> 왼쪽 메뉴 아래 secrets and variables ->Repository secrets
에 각각 하나씩 저장한다.
파일 올리기는 안된다 직접 복사해서 붙여넣기한다.

AWS EC2는 항상 보안그룹 -> 외부에서 접근(인바운드규칙!)
scp(파일전송, SSH) 22번 포트 사용

웹서버 있는지 확인(Nginx)

EC2계정 ubuntu 아니면 꼭 계정확인 var/www/html

모바텀으로 가서 EC2 접속해서 권한 확인 명령어 
ls -ld 폴더위치작성!
ls -ld /var/www/html

권한 변경 (chmod)
유저 변경 (chwon)
sudo chown ubuntu:ubuntu /var/www/html
